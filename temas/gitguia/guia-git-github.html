Guia Prático: Fluxo de Trabalho com Git e GitHub

Este guia cobre os três principais fluxos de trabalho com o sistema de controlo de versões Git e a plataforma de *hosting* GitHub. Esteja sempre atento à autenticação via **Token**.

Sumário
  • 1. Glossário Essencial de Comandos
  • 2. Fluxo A: Do GitHub para o PC (Clone - Commit - Push)
  • 3. Fluxo B: Do PC para o GitHub (Init - Add - Commit - Push)
  • 4. Fluxo C: Web Pages com GitHub (GitHub Pages)

1. Glossário Essencial de Comandos

Abaixo estão os comandos fundamentais utilizados neste guia:

[cite_start] [cite_start] [cite_start] [cite_start] [cite_start] [cite_start]
Comando/Termo Função Comando de Exemplo
**`repo`** Repositório. O projeto onde o histórico de versões é guardado.
**`commit`**Guarda uma "fotografia" (*snapshot*) do estado atual dos ficheiros que foram preparados (*staged*) no seu repositório local[cite: 166].`git commit -a -m "Mensagem"` [cite: 166]
**`clone`**Copia (clona) um REPO da nuvem (GitHub) para o nosso PC[cite: 166]. `git clone https://www.merriam-webster.com/dictionary/repo`
**`add`** Adiciona as alterações (novos ou modificados) à área de preparação (*staging area*) para o próximo commit. `git add .` (Adiciona todos os ficheiros modificados)
**`push`**Envia as alterações do repositório local (commits) para o GitHub (nuvem)[cite: 166].`git push origin main` [cite: 219]
**`pull`**Trazer as alterações mais recentes do GitHub para o repositório local[cite: 166]. `git pull origin main`
**`status`** Mostra o estado da pasta de trabalho e da área de preparação (ficheiros modificados, preparados ou não monitorizados). `git status`

2. Fluxo A: Do GitHub para o PC (Clone - Commit - Push)

[cite_start]

Este é o processo mais comum para começar a trabalhar num projeto que já existe no GitHub[cite: 176].

Passos do Fluxo

    [cite_start]
  1. Criação do Repositório (REPO) no GitHub (Pode incluir `Readme.md`)[cite: 170, 177].
    2. [cite_start]
  2. O REPO é **clonado** para o PC local[cite: 171].
    3. [cite_start]
  3. Geração do **Token** e Autenticação no REPO (necessário para *push* em muitas configurações)[cite: 172, 179].
    4. [cite_start]
  4. **`commit`**: As alterações locais são guardadas[cite: 173].
    5. [cite_start]
  5. **`push`**: As alterações são enviadas para a nuvem[cite: 174].

A.1. Clonar o Repositório

Use o URL do GitHub (HTTPS) para descarregar o REPO para o seu PC.

CMD - Trazer o repo para o pc

C:\GitLab\Projetos> git clone https://github.com/profcarlos2006/novo5.git

Resposta:

Cloning into 'novo5'...
remote: Enumerating objects: 3, done.
...
Receiving objects: 100% (3/3), done.

A.2. Autenticação (Configuração Inicial)

Antes de fazer o primeiro *commit*, autentique-se, se necessário, e configure a sua identidade Git.

CMD - Configurar utilizador (apenas na primeira vez)

git config --global user.name "profcarlos2006"
git config --global user.email "profcarlos2006@gmail.com"

**Importante:** Gere um **Token** no GitHub (Settings > Developer Settings) e guarde-o num local seguro. [cite_start]Será necessário para o comando `git push`[cite: 179, 181, 182, 183, 184, 186, 187].

A.3. Fazer Alterações e Commit

[cite_start]

Depois de fazer as alterações (e.g., alterar o ficheiro `Readme.md`), use `git commit` para as guardar localmente[cite: 204].

Primeiro, verifique o estado:

C:\GitLab\Projetos\novo5>git status

Resposta (Alterações não preparadas):

Changes not staged for commit:
    modified:   README.md

Em seguida, faça o commit (usando a flag **`-a`** para incluir automaticamente os ficheiros modificados):

C:\GitLab\Projetos\novo5>git commit -a -m "primeira alteração ao novo 5"

Resposta (Commit efetuado):

[main a2e7211] primeira alteração ao novo 5
1 file changed, 2 insertions(+), 1 deletion(-)

A.4. Enviar para a Nuvem (Push)

[cite_start]

O `push` envia os commits locais para o repositório remoto no GitHub[cite: 218].

CMD - Enviar os ficheiros para a nuvem

C:\GitLab\Projetos\novo5>git push origin main

Resposta:

...
Total 3 (delta 0), reused 0 (delta 0), pack-reused 0 (from 0)
To https://github.com/profcarlos2006/novo5.git
3fedd54..a2e7211  main -> main

3. Fluxo B: Do PC para o GitHub (Init - Add - Commit - Push)

[cite_start]

Este fluxo é usado quando tem um projeto local existente e deseja começar a controlá-lo com Git e colocá-lo no GitHub pela primeira vez[cite: 229].

B.1. Inicializar o Repositório Local

[cite_start]

Transforme a pasta do seu projeto num Repositório Git local[cite: 232].

CMD - Transformar a pasta num REPO

C:\GitLab\Projetos\novo6>git init

Resposta:

Initialized empty Git repository in C:/GitLab/Projetos/novo6/.git/

CMD - Verificar o estado (os ficheiros ainda não estão monitorizados)

C:\GitLab\Projetos\novo6>git status

Resposta:

Untracked files:
        readme.txt

B.2. Preparar e Cometer Ficheiros (Add e Commit)

[cite_start]

Use `git add .` para preparar todos os ficheiros e `git commit` para guardar a primeira versão[cite: 232].

CMD - Preparar os ficheiros para commit

C:\GitLab\Projetos\novo6> git add .

CMD - Fazer o primeiro commit

C:\GitLab\Projetos\novo6>git commit -a -m "primeiro commit do novo6"

Resposta:

[master (root-commit) 94621fc] primeiro commit do novo6
1 file changed, 1 insertion(+)

B.3. Ligar ao GitHub e Fazer Push

Crie um REPO vazio no GitHub. Depois, ligue o seu REPO local ao REPO remoto e envie os ficheiros.

CMD - Ligar o REPO local ao REPO no GitHub (URL do REPO Vazio)

C:\GitLab\Projetos\novo6>git remote add origin https://github.com/profcarlos2006/novo6.git

CMD - Enviar para GitHub

C:\GitLab\Projetos\novo6>git push origin master

Resposta:

...
To https://github.com/profcarlos2006/novo6.git
 * [new branch]      master -> master

B.4. Sincronizar com Pull

[cite_start]

Se alguém alterar o ficheiro na plataforma GitHub, utilize `git pull` para trazer as alterações para o seu PC[cite: 232].

CMD - Trazer do GitHub

C:\GitLab\Projetos\novo6>git pull origin master

4. Fluxo C: Web Pages com GitHub (GitHub Pages)

[cite_start]

O GitHub Pages permite-lhe hospedar um website estático diretamente a partir do seu repositório[cite: 233].

Passos Chave para o GitHub Pages

    [cite_start]
  1. Crie o REPO no GitHub[cite: 240].
    2. [cite_start]
  2. Crie um **branch** com o nome **`gh-pages`** (ou use a branch `main` e defina-a nas *Settings*)[cite: 240].
    3. [cite_start]
  3. Altere o *default branch* para **`gh-pages`** nas definições (Settings > Branches)[cite: 240].
    4. [cite_start]
  4. Vá a **Settings > Pages** para aceder aos dados e configurações da página[cite: 240].
  5. Trabalhe na branch `gh-pages` localmente.
    6. [cite_start]
  6. Faça o **`push`** para a branch `gh-pages` remota para publicar o site[cite: 240].

C.1. Fazer Push para a Branch de Publicação

[cite_start]

No terminal, depois de ter clonado o REPO (Passo A.1.) e feito o *commit* dos seus ficheiros web (`index.html`, etc.), envie-os para a branch **`gh-pages`**[cite: 240]:

CMD - Enviar os ficheiros para a branch `gh-pages`

C:\GitLab\Projetos\web1>git push origin gh-pages

Resposta:

...
To https://github.com/profcarlos2006/web1.git
   b528447..a3a832c  gh-pages -> gh-pages
[cite_start]

Após alguns minutos, o seu site estará ativo no URL que aparece em **Settings > Pages**[cite: 240].
